# voice/ —— 语音线：流程与配置（不含声卡数据本体）

> ⚠️ **本目录不包含任何声卡/音色数据**。本框架作者使用的角色声卡由已停运手游的解包音频训练而来，属衍生素材，**永不入库**。这里提供的是「如何为任何角色重建声卡」的完整流程与配置模板。

## 重建一套角色声卡要做什么

1. **取得可合法使用的底片**：你自己录制的音频，或授权明确的素材（流程模板不内置任何底片）。
2. **切段与转写**：按静音检测切底片、生成转写侧车文件（配置见 `pipeline/`）。
3. **TTS 引擎定档**：参考 `config/gsv-v5turbo.example.yml`（GPT-SoVITS v5 turbo）——采样参数矩阵、防复读/防死循环的参数取舍都有注释。
4. **确定性复现验收**：固定 seed 重跑，输出与定档参考件 MD5 逐比特一致才算定档（这是本框架语音线的验收家法）。
5. **长文本生产**：按语义切片（20-40 字/片）→ 逐片合成 → ffmpeg 拼接；整段直呼在长文本上韵律漂移，切片是生产线的骨架。

## 已入库

- `gsv-openai-proxy.py`：语音壳——OpenAI 兼容转换层，前端 TTS 请求的统一入口。职责：按角色分声路由、切片合成、**round-trip 质量闸**（合成完喂回 ASR 回读：字数比与片头拼音比对，可疑自动重骰）、RVC 染色接线、ffmpeg 拼接。

## 已知坑速览（细节随模块迁移补全）

- 跨语种合成的「大佐味」是引擎通病，微调不根治，选好底片更有效。
- 收紧采样是双刃剑：过度收紧诱发复读或死循环，定档参数以实测为准。
- 引擎热切换接口会把参数持久化写回配置文件，改完记得回读。
