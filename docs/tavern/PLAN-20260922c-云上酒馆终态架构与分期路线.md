## 三、2C8G 资源账（结论：够）

ST ~0.3G + n8n ~0.5G + Qdrant ~0.5-1G（4.5K 点小库，mmap）+ MemPalace 热态 ~0.5G（ONNX 嵌入）+ 系统/docker ~1G ≈ **稳态 2.5-3.5G**，余量充足；全 I/O 型负载 2 核够。配 2G swap 防 n8n 尖峰；磁盘 20G 级即可。

## 四、关键架构选择：手机在外的「大脑」

- **方案 A·云端 API**（如 GLM glm-5.3-flash，已有 key）：零 GPU、原生云、一期即可跑通。代价：人味/开放度不如本地 35B，API 有内容边界与额度节奏（5h 窗+周额度，高峰 1.5×）。
- **方案 B·穿透回家**：全质量本地 35B+双声朗读，代价=家里机器常开+穿透暴露面。
- **裁决建议**：A 打底跑通全链，B 作为四期升级包——两者切换=酒馆换 custom endpoint，记忆库不动，无缝。

## 五、安全红线清单（动工前必读）

1. **Qdrant/MemPalace 绝不裸公网**：docker 内网互联，仅 ST/n8n 可达；Qdrant 设 API key。
2. 云防火墙只开 443，Caddy 反代 + HTTPS；ST 开 basicAuth，n8n 已有 owner 认证。
3. 备份：云卷（ST data / Qdrant storage / MemPalace palace / n8n db）定期 dump 回本地，对齐四备份纪律。
4. 内网穿透选型（四期再动）：自有云服务器 → **frp 自托管**（云=frps 家=frpc）或 SSH 反向隧道，不依赖第三方；追求零开端口 → Tailscale。llama-server/TTS 桥加访问控制后再暴露。

## 六、分期路线（每期独立可验收）

- **一期·记忆中枢上云**：docker-compose 起 Qdrant+MemPalace（挂卷+密钥）→ 本地 L4 链的 6333 调用改指云端 → 本地全链冒烟（记忆读写+人生记忆捞取）。验收：本地聊天体验不变，云上能看到 chat_memory 增长。
