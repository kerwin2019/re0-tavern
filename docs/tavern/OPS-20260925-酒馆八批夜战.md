## 二、坑与问题（症状+报错原文+复现条件）

1. **流式中继三层洋葱（本夜最大收获，v3.4.0 起潜伏至今）**——批4 冒烟 `stream:true` 连炸三刀：
   - ① `错误: '_GeneratorContextManager' object has no attribute 'status_code'`——原代码 `r = httpx.stream(...)` 后裸调 `r.__enter__()` 不接收返回值，CM 对象上取属性必炸。**v3.4.0-3.4.4 每一次流式请求都炸**，ST 一直非流式所以从没炸到人（此前"流式只差 ST 开关"的判断是错的，冒烟实弹才现形）。
   - ② `错误: 'Response' object does not support the context manager protocol`——第一刀修成 `httpx.stream(...).__enter__()` 后，尾部 `with r:` 炸：httpx Response 不是 CM。
   - ③ `错误: Attempted to read or stream content, but the stream has been closed.`——第二刀去掉 with 后仍炸：`r = httpx.stream(...).__enter__()` 链式写法让 **CM 对象匿名无引用，CPython 引用计数立刻回收 → 内部 with 块退出 → 响应流被关**，iter_lines 时流已死。
   - **终修（v3.4.7）**：`cm = httpx.stream(...)`（保引用）+ `r = cm.__enter__()`；429 体读 `r.read()`、关流一律 `r.close()`；iter 段 try/finally+r.close()。fast/pure 双路 SSE 逐字出块实证通过。
   - **家法候选：凡 httpx.stream 必须三件套——CM 存变量、__enter__ 接收、close 用 r.close()**。
2. **WinSCP call 15 秒无通信自杀**：盲测脚本双连发（2×纯档生成 ≈300s）同步 call → `主机超过15秒无通信…警告：中止这个操作为关闭连接` 会话被掐。**但孤儿进程在服务器把测试跑完了**（[recall] 07:08/07:10 两行即它写的）——长活必须 setsid 脱会话+分次 poll（知识册 §部署3 今晚再实证）。
3. **多层引号咬变量**：`call bash -c "…\"$F\"…"` → `$F` 被外层展开成空，`head: cannot open '/chat-export.json'`。家法重申：逻辑一律写 .sh 文件上传执行。
4. **本地 printf 造 WinSCP 脚本必炸**：`printf 'C:\\Users…'` 报 `printf: missing unicode digit for \U`，且 `\t` 被转成制表符咬断路径（Temp\test → Temp+TAB+est）。WinSCP 脚本一律 Write 工具落盘。
5. **怪目录挡路**：`/root/work/cloud-config/test_v341_fast.sh` 是**目录**，内含 2211 个 `.tmpXXXX`/40 位哈希名**空目录**（06:48 集中生成，来路不明，疑并行会话手笔）→ put 被迫跳过、call 报 `Is a directory`（退出码 126）。处置=改名 `test_v341_fast.sh.dir-bak-20260925` 隔离未删（挪后删纪律）；cloud-config 内未扩散，磁盘 63% 正常。
6. **GLM low 摘要超长**：prompt 写 150-300 字，实测 bootstrap 866 字、第 80 轮触发 1085 字。v3.4.4 掐 prompt「严格不超过 300 字」+max_tokens 768，下个 20 轮窗口验证。
7. **st-live 计数触发器**：chat_memory 每轮+2 点，count%20==0 触发摘要——测试轮会推着计数走（76→84），属正常但验收时要算进去。
