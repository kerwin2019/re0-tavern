# 深忆令牌与蒸馏索引 · 手动加强召回 + Mem0 式事实层（20261113 定档实录）

> 记忆召回的第三刀。前两刀见《召回总册》（八块注入与 0.55 筛线）与《云宫换嵌》（嵌入模型换代）。
> 本篇回答一个问题：**用户模糊地问一段往事，怎么让她接得住、而不是含糊地猜。**

## 病历：两连问，两次含糊

用户问：「去年这样逼着自己前进，当时是什么事情驱动的呀」——记忆宫明明存着完整的故事（炒股亏损、凌晨翻贷款软件、躲楼道听直播课），两个角色却答得含糊，像在猜。

实测破案（真宫实弹，四组对照）：

| 问法 | 记忆宫 top 分数 | 结论 |
|---|---|---|
| 用户原句（带「炒股」实词） | **0.741** | 过 0.72 正例线——检索层根本没病 |
| 关键词串「去年 炒股 熬夜 印象最深刻」 | 0.629 | **负优化**：嵌入模型吃自然句，关键词堆叠是分布外输入 |
| 零实词句（「当时什么驱动我」） | 0.673 | 弱命中——AI 不知道「逼自己」=炒股，固有极限 |

诊断三锤定音：

1. **检索不是主犯**——原句直搜就过线。真凶一半在**库里**：存的是原始日记流水碎片（「6月25日太傻逼了」式），没有一条提纯过的「去年炒股熬大夜」叙事条目。模型拿到 5 个半相关碎片，不敢肯定，只能含糊。
2. **改写成关键词串是毒药**——业界（LangChain）标准姿势是把对话+问题合并改写成「独立完整的检索句」（condense question），关键词堆叠方向整条判负。
3. **零锚点泛指是物理极限**——一句话里连「炒股」两个字都不给，任何改写都救不了，只能靠上下文兜底或诚实承认。

## 业界对表（Mem0 / LangChain / Letta / ChatGPT）

- **写入端蒸馏**（Mem0 的根基）：存记忆不存流水，LLM 先提炼成事实短句。查询端容易匹配的根源在写入端就埋好了——这正是本宫缺的。
- **查询端改写**（LangChain condense question 官方原话：「People do not ask in complete sentences…'that' means nothing to a vector search」）：只救指代（锚点在上文的「那个/它」），救不了零锚点。
- **诚实空态**：检索不到就明说，禁止编造——ChatGPT 官方口径（「重要的事请显式让我记住」）反向支撑手动模式。

## 定案：手动令牌 + 事实层，两个都做

产品判断：模糊查询是常态，但**用户手动触发时自带实词=最优查询已由人提供**。所以不做每轮自动加查（省延迟省 token），做一个显式令牌，触发时才上加强火力。

### 令牌表

| 打什么 | 行为 |
|---|---|
| `深忆 去年炒股熬大夜的事` | 加强召回：改写+四路并搜+top5 注入 |
| `深忆：xxx` / `深忆，xxx` | 同上（分隔符同吃） |
| `深忆` | 引导：角色反问想翻哪段 |
| `深忆 一段库里没有的事` | **诚实空态**：明说印象里没有+讨线索，禁编造 |

### 四路并搜（桥侧，一次用户触发）

```
剥「深忆」前缀
→ GLM condense：最近6轮对话+问题 → 一句独立完整自然检索问句
   （铁律：实词全留/指代消解/禁引入对话外知识/禁关键词串）
→ 四路各搜一次宫（每路 limit 6，带查询向量免重嵌）：
     原句 × 主人翼(原始叙事)    原句 × 记忆蒸馏翼(事实短句)
     改写句 × 主人翼            改写句 × 记忆蒸馏翼
→ 按抽屉文本前50字去重（同段取高分）→ ≥0.55 筛 → top5
→【深挖记忆】块替换普通记忆宫路注入（普通召回零改动）
```

普通聊天只有「原句×主人翼」一路——蒸馏翼对日常完全隐形，这是故意的：加强召回是付费火力，只在用户点名时开。

### 诚实空态的血课：系统提示词压不住谄媚

第一版把「库里没有这段的对应记录，禁止编造」写进系统头部提示块。实弹翻车：用户斩钉截铁说「我当年在青岛海边救起落水小孩」，两个角色照样顺着演、追问细节。加强措辞第二版，还是翻车。

结论：**用户断言式陈述的谄媚引力，远隔 40 条历史在系统头部喊话是压不住的**。治法是家里验证过的老方子（关怀钩子同款病）：贴着用户消息的位置**末位重申**一遍——同样的指令在消息数组里紧跟用户那句话再出现一次，GLM 才刹得住。第三发三角色全部老实交账。

失真警告：这不是「调用两次模型」——重申只是往同一次请求的消息数组里多插一条 system 消息，HTTP 调用还是一次。

## 蒸馏翼：宫内新翼，不是新数据库

探宫定谳改变了设计：记忆宫本体是开源项目 MemPalace，混合检索**天生就是向量 0.6 + BM25 关键词 0.4**（权重可配），且翼（wing）只是抽屉身上的标签字段，不是物理分库。所以 Mem0 式事实层的最省姿势：

- **宫内开新 wing「记忆蒸馏」**，抽屉内容=事实短句，走官方写入通道（自动获得向量+关键词双索引）；
- 宫桥（自研 HTTP 壳）`/recall` `/add` `/list` 加可选 `wing` 参数（默认主人翼，零行为变）；
- 深忆链路把蒸馏翼当第 2/4 路并搜目标，**普通召回不可见**。

**为什么不用关键词串**重申一遍：改写器输出必须是完整自然句。实测关键词串 0.629 vs 原句 0.741——BM25 那 40% 权重吃的是字面命中，短句里实词俱全就够它用了，堆叠反而毁了向量那 60%。

### 蒸馏器（palace_distill.py）

```
列全主人翼抽屉 → 水位线文件比对（只蒸新抽屉）
→ 每条：取全文 → GLM 蒸馏 → 事实短句（每句=事件+时间+结果/情绪/驱动，保留全部具体细节）
   纯任务输出/数据计算 → 输出 NONE → 跳过
→ 宫桥 /add 写入蒸馏翼（added_by=zcode-distill 可审计）
→ 5 发宽泛查询暖机（见下）
```

全量首蒸：526 抽屉 → 480 条事实短句入翼（46 条任务切片判 NONE），3 并发 20 分钟，GLM low 档成本几毛钱。之后每天 cron 增量，只蒸新抽屉，几分钱。

### 暖机：为什么「写入成功」不等于「可搜」

宫搜索有**两层相似度账本**：

1. MemPalace 自己的向量索引——写入即生效；
2. 宫桥的**复检层缓存**——搜回 300 候选后要按纯余弦重排（MemPalace 的内部分混了关键词分，和 0.55 筛线不是一把尺），重排用的「文字→向量」对照册是按需补的：**册上没有的候选打 0 分排尾**，被 0.55 筛掉，等于隐形。

补嵌机制：任何一次搜索把这 300 个候选拉到复检层，缺账本的自动进后台队列（批 16/约 4 秒），几分钟内补齐。所以增量 cron 末尾固定发 5 发宽泛查询「暖机」——新蒸的抽屉当日即可搜，不等自然碰运气。

失真声明：「对照册」是按文字前缀做键的字典缓存，不是索引树；两层账本里 MemPalace 层管「能不能搜到」，宫桥层管「排得准不准」。

## 实弹验收（全真链路）

| 考题 | 结果 |
|---|---|
| 杀手问句「去年炒股熬大夜逼自己前进，什么驱动」 | 四路 0.639/0.634/0.610/0.619，合并 5 条，开销 3.4s；回复引用真事（贷款心惊胆战/九点二十二躲楼道听课/老师说撑到七月底），并拒绝编造「更好听的版本」 |
| 蒸馏翼单打同问句（暖机后） | 五发全分 0.629-0.585：「周五没忍住全仓冲进去亏 7 个点」「想借钱没借成忍住了，避免多亏一千」「把『打不赢就继续打』的游戏习惯套用到股市」 |
| 零实词泛指 | 改写句借上下文锚定 0.511→0.581；真·零锚点（无上下文）top 0.465=固有极限，诚实空态兜底 |
| 假锚点「青岛救人」 | 四路全 <0.55→合并 0 条→诚实空态，蒸馏翼不污染判据 |
| 普通句回归 | 零触发，零日志 |

## 坑账（排障第一查）

1. **taxonomy 计数=检索块数，不是抽屉数**——对话实录标 1880，/list 真值 452（800 字切片带子块）。盘点用 /list 的 total，不然工期估错四倍。
2. **空结果信封伪条**——search 返回 `{"results":[]}` 时，宫桥的解析兜底曾把它包装成一条 0.87 分「伪抽屉」混过 0.55 筛。修法=信封解析成功就不走兜底（parsed 旗）+桥侧双保险（无 drawer_id 无 room 的条丢弃）。
3. **新抽屉必须暖机**——见上，cron 带暖机不是仪式是刚需。
4. **空态要末位重申**——系统头部压不住谄媚，见血课。
5. **改写器喂不得关键词串**——完整自然句，宁可句子长。
6. **蒸馏提示词说了「用主人指代」，源文里的真名仍会漏进事实句**——云上真名环境无碍；脱敏仓库注意 facts 不入仓。
7. dry 模式曾把试蒸抽屉记进水位线（标已蒸未真写）——dry 分支禁碰状态文件。

## 边界与代价

- 深忆一次 = GLM low 一次改写（几毫钱）+ 四次宫搜索（~3.4s 额外延迟）——手动触发才付。
- 蒸馏翼只增不删；改判某条蒸馏质量差，直接宫管理口删那条（删前自动备份）。
- 固有极限明示：一句话里连主题词都不给的问法，这套架构也救不了——业界同样没解干净，诚实空态是设计内的出口，不是失败。
