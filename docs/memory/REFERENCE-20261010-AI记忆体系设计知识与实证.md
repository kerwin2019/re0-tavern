## 一、问题定义：常驻记忆是一笔「每轮税」

AI 记忆分两层：**常驻层**（每轮对话全文注入：宪法/守则 + 记忆索引）和**检索层**（躺在盘上按需读：知识库/卡片正文/技能手册）。常驻层的每一行都是固定成本：

- **token 税**：本机实测，索引 123 条 ≈7,500 token + 守则 ≈3,600 token = **每轮 ≈11,000 token 固定开销**。200 轮会话 = 222 万 token 白烧在重复阅读同一份目录上。
- **注意力税（更贵）**：指令遵循率随指令条数非线性衰减（IFScale，arXiv 2507.11538）——前沿模型 100 条指令还能 ~90% 遵守，500 条掉到 40-70%；且「高准确率≠高可靠」，可靠性口径下再掉 18 个点。**不是模型不听话，是每条规则的遵守力度被稀释了**——你精心写的核心规则和顺手加的一条备注，在它眼里没有优先级差异。
- **噪音税**：ETH Zurich（arXiv 2602.11988）实测——AI 自己生成的守则让 agent 成功率 **-3%**、成本 +20%；把仓库已有文档剥掉后 AI 生成文件反而 **+2.7%**：**与既有资料重复的内容 = 纯噪音**。上下文文件只该装「agent 自己发现不了的非显而易见信息」。

## 二、索引膨胀的病理（为什么越管越胖）

GitHub anthropics/claude-code#79217（同病案主帖+8 跟帖，全部实测派）：

1. **修剪跑不过增量**：某项目 30 天里 95 次提交中 **12 次在压缩索引**，其中一次整笔提交只砍掉 **9 字节**；单次修剪回收 0.52K，而两次修剪之间自然增长 0.9K——**修剪在数学上必输**。光靠定期删字救不了索引。
2. **索引行的条款是怎么长出来的**：每一行多余条款都是一个**刚被坑过的会话**加上去的（「一行指针不够保险，补个条件」）。所以压缩压力挤掉的不是冗余——冗余本来就没有——而是**承重约束**（触发条件/血案注记），失效是静默的，直到哪天再踩同一个坑。
3. **不可满足的压缩目标**：官方压缩提示要求「one line per entry」+「under 140 lines」——当记忆有 146 条时这两个要求**数学上不可同时满足**，唯一能动的杠杆就只剩「删用户的记忆」。有 agent 真的照做了，一轮悄悄删掉 40 张卡。
4. **截断是静默的**：超线的部分下次会话直接消失，加载时没有任何警告。

## 三、六条设计原则

1. **神经反射 vs 场景查阅**：动手那一秒就要用的（报错先搜/删除先挪回收站）→ 常驻；到了特定场景才查的（操作手册/工单模板/病历）→ 写成「做 X 前先读 Y」的指针。判据不是使用频率，是**触发时机**。
2. **两测试**：①删掉这条 AI 会犯错吗？会→留。②AI 自己能发现吗？能→删（重复信息实证=负资产）。
3. **目录行不能砍到零**：703 会话实测——索引行直接命中的召回价值 = 一跳之外按需查询的 **1.7 倍**；纯按需查询的跳转率只有 **2.6%**。「AI 不会去查它不知道存在的东西」——hub 化的每一步都要对冲这个衰减：hub 行带强触发词，hub 正文逐字保留子卡钩子。
4. **短而稳的偏好直接进索引**（dev.to 共识）：「永远用 bun」「未经确认不自动 commit」这类一行规则放索引直挂；主题文件 5-10 张是甜点区，多了索引自己就胖了。
5. **skill=程序性知识，卡片=状态与数据**：「条件→行动」的操作流程（怎么选 API 通道/怎么跑夜战）抽成技能按需挂载；状态数据（现役模型/额度/端口）留卡片，技能只装路标不存数据——数据会变，技能里的数字放半年就成毒药。
6. **容量按 UTF-16 单位算，不按磁盘字节**：官方「25KB」截断线实为 25,000 UTF-16 单位；中文每字 1 单位（磁盘上 3 字节）。按字节估余量会**高估 3 倍用量**——反过来说，中文索引比看起来耐用。全部金丝雀都是 ASCII 时这个错误永不暴露（跟帖实测原话）。

## 四、hub 化架构（本机实战落地版）

```
MEMORY.md（每轮注入，目标 <6K 字符）
├── 直挂层：反射/承重/当周活跃（12 行）
├── hub 层：一域一行 ×12（画像/多窗/课堂/生图/酒馆桥/语音/调优/API/基建/壳/坑册/小件）
│     └── hub 正文 = 子卡一览（每卡一行原钩子**逐字保留**）
├── INBOX 区：新索引行先落这里，月度审计才归位
└── 金丝雀行：文末标记行，新会话引不出 = 索引被截断，立即报警
```

- **零概括改写**：hub 正文抄原钩子，不写摘要版——概括 = 压缩压力挤压承重条款的同族病。
- **每卡必有一行可达**：要么索引直挂、要么所属 hub 正文（防孤儿档；语义检索不覆盖记忆目录时，索引是唯一召回通道）。
- **触发词三件套**：人话高频词（不是术语）+ 场景词（「…时」）+ 最强标记词（🩸血案/⭐用户令）。
- **重组只许专门作业做**：会话中途禁重排索引——中途有损重组是最大的静默丢失源（跟帖实测）。
- 效果（本机 1010 实测）：索引 123 条/14,667 字符 → **24 条/3,095 字符**；常驻合计 **11,100→5,360 token（-52%）**；指令密度 210+→~120 条，回到可靠区。

## 五、手术纪律（删/并/迁的流程闸）

1. **逐字 diff 回执制**：删除任何索引行前，先 rg 出声称覆盖它的宪法/技能/KB 原文，逐字比对贴回执——**对得上才准砍**。实战数据：7 个删除候选里 2 个假覆盖（28%），全靠回执制逮住（其中一张卡的独有规则反过来回填进了守则）。
2. **先回填后删行**：卡内独有内容先搬进正本（守则/技能/知识库），确认落盘后才删卡。顺序不可反。
3. **整条搬家禁原地压缩**：语义零丢失，宁胖勿压（省 1,000 token < 犯错重试 5,600）。
4. **合并判据=真同题**：血案学案≠工具卡≠活跃项目——塞错域的 hub 会破坏语义一致性，一跳触发词全部失灵。
5. **翻案不是失败**：验证制逮住假覆盖=制度在工作。

## 六、技术陷阱清单（踩过的坑）

| 陷阱 | 要点 |
|---|---|
| 静默截断 | 超线部分下次会话直接消失，无加载警告——金丝雀行是唯一廉价探测器 |
| UTF-16 vs 字节 | 中文 1 单位/字、磁盘 3 字节/字；容量预算必须按单位算 |
| 金丝雀盲区 | canary 全 ASCII 时单位=字节，多字节内容下误差静默——金丝雀本身要含非 ASCII |
| 中途重排 | 会话进行中重组索引 = 最大静默丢失源；重组只许专门作业 |
| 多窗互踩 | 常驻文件以会话启动快照注入，他窗改了盘上文件老窗看不见——改前必重读磁盘最新版 |
| 删行=断召回 | 语义检索没覆盖记忆目录时，删索引行=该卡从此不可发现（只剩全盘 rg 兜底） |
| 概括成瘾 | 摘要钩子丢了触发条件和血案注记=承重约束静默死亡 |

## 人话版

**一句话**：AI 的随身记忆是一笔每轮都交的税——交太多它就变笨（指令多了记不住），交太少它会忘事；这门手艺的核心是「把税交在刀刃上」。

**白话版**：把常驻记忆想成一张贴在墙上的便签墙。便签越贴越多，每一条被认真看的概率就越低（实验证明：指令超过一百条，遵守率开始崩）；而把便签撕掉又怕撕掉的是救命的那张。业界实测给出的答案是：墙上只贴「动手前那一秒要看」的反射规则和一张「房间目录」，每个房间（领域）的门上挂一块小牌子写清里面有什么，东西全放房间里的档案盒——要用的翻目录找房间，翻牌子就知道去哪拿。三个保命细节：①撕任何便签前先拿原件对账（实测 28% 的「别处已有」是假的）；②牌子上的字照抄不概括（概括会丢触发条件）；③墙末尾贴一张验钞纸，下次进来念不出来=墙被截断了，赶紧报修。
