# OPS-20260923-语音糊音破案（浮点整数一字节错）与破折号清洗

> **一句话**：拉姆长句语音「呼噜+电流」的真凶 = cosyvoice 代理拼接 WAV 时把 **float32 格式标签硬编码成整数 PCM**（一字节错，0917 起病）；辅因 = 长句响度爬升（漏配 LoudNorm）+ 「──」符号喂引擎。三层全修，根治版频谱黑底、电平达标。
> **来源**：2026-09-23 凌晨主窗口实战。关联：`REFERENCE-20260922-坑账总册` §十四.6/7 · `OPS-20260922b-晨间五件新活.md`（响度爬升初诊）· 检查点 0923 凌晨 II。

## 一、破案链（五步定罪，每步都可复现）

1. **耳审分向**：同段长文 A/B（前半拉姆染色/后半蕾姆染色）→ 前糊后净 → 染色环节定罪（用户耳判）。
2. **电平反常**：无染色原声 mean_volume = **-6.0 dB**、峰值均值差仅 2dB——正常语音均值 -18~-25、crest 12-20dB。crest 2dB 物理上不可能是正常语音 = 波形被削成方波。
3. **频谱定型**：afftdn/anlmdn 双降噪洗不动 → 噪毯与语音包络同步起伏 = **相关谐波失真**（切削产物），不是加性嘶噪——降噪器对相关失真无能为力。
4. **分辨实验**：同 92 字长文**绕过代理直连服务器 = 干净（-31.5dB）**；代理切开的每片单独直连 = 也干净；**用代理自己的 parse_wav/make_wav 复刻拼接 = 脏音复现（-6.0dB）**。
5. **逐字节验尸**：服务器 WAV 头 fmt 标签 = **3（IEEE float32）**，代理 make_wav 硬编码 = **1（整数 PCM）**。浮点 0.5 被读成整数 10.6 亿 → 整条音频爆表削波。

## 三、客观验证口径（以后音频案照此测量）

- `ffmpeg volumedetect`：mean/max 差值（crest factor）<8dB 即可疑
- `ffmpeg -af ebur128`：I（整体响度）+ LRA（响度范围）——修复前 LRA 16.6 乱窜，修复后 **1.8** 纹丝不动，I=-18.6 正中靶
- `showspectrumpic` 频谱图：黑底条纹=健康；全频段亮毯=失真或嘶噪；**与语音同步起伏=相关失真（降噪无效），恒定亮毯=加性嘶噪（降噪有效）**

## 四、残留与观察

- 染色抽卡非确定性（rvc_wrap 自注）依旧存在——但喂干净输入后预期大幅好转；若仍糊，下一档=拉姆 ir 0.5→0.35 或长句按句切分染色
- 「响度爬升病 +3.7dB」（0922b 初诊）实为本案症状之一，LoudNorm 保留（有益无害）
- 语音已按用户令搁置（云预演期）：恢复语音时 cosyvoice server+proxy 照 start-chat-stack.ps1 拉回即可，根治补丁永久生效
