# OPS-20261011-管理台小票非法路径修复v231

> 立档：1011 用户报「酒馆管理台，运行小票点记录显示 读取失败：非法路径」。本档=全案：根因/修法/验法/证据。

## 一、症状与根因
- **症状**：管理台（:5679）「运行小票」签列表正常，**点任何一条记录**弹「读取失败：非法路径」。1004 以后点开必坏。
- **根因**：`/root/work/logs` 自 **1004 20:27 起是软链**（→`/root/data/logs`，盘位迁移产物）。列表接口 `_receipt_list` glob `/root/work/logs/turn_receipt-*.jsonl` 返回**未解析路径**（列表正常）；详情接口 `_receipt_detail` 把前端回传路径 `os.path.realpath()` 解析后与**未解析的原始前缀** `/root/work/logs/turn_receipt-` 比对——realpath 解出 `/root/data/logs/...`，前缀必失配 → 恒返 `{"error":"非法路径"}`。
- **为何现在才爆**：1004 软链建立前该校验一直成立；小票详情属低频点击，10 天没人点。
- **同文件对照**：`/api/review/img`（v2.2.0 目审台）既有写法就是正确范式——`fp.startswith(os.path.realpath(REVIEW_ROOT) + os.sep)`，基准同样 realpath，所以目审台没坏。

## 二、修法（console v2.3.1，云端 git d5a989c）
一行改动 + 版本行：
```python
# 旧
if not safe.startswith("/root/work/logs/turn_receipt-"):
# 新（基准同样 realpath，防穿越能力不变）
if not safe.startswith(os.path.realpath("/root/work/logs") + os.sep + "turn_receipt-"):
```
- 家法全走：补丁脚本 scp 上云跑（禁 ssh 内联 python）→ 改前 `.bak` 备份 → `py_compile` 过 → 重启 → HTTP 实弹 → 点名 `git add tavern-console.py` 一案一 commit。

## 三、验法（HTTP 实弹，verify_receiptfix_20261011.py）
- 正例：`/api/receipt/list` 9 天日期正常 → 取当日首条记录 POST `/api/receipt/detail` → 返回**完整小票 12 键**（ts/mode/provider/timings/injections/recalls/writes…），不再是「非法路径」。
- 负例×2（防穿越不回退）：`/etc/passwd` → `非法路径` ✓；借软链目录 `/root/work/logs/../../etc/passwd`（realpath 解析落 `/etc/passwd`）→ `非法路径` ✓。
- 验收脚本首版误报一次：小票正文自带 `error: null` 字段被当成接口报错——**判据教训：该接口报错=单键 `{"error":"<文案>"}`，正常返回=多键完整小票**。
